详细字段与后续兼容门禁见 导入导出标准。Schema 的 v1 URI 为稳定标识；新版本单独增加 Schema，不覆盖第一版。此前 0.2-draft 容器及 0.3-draft 步骤仅作为已生成文件的读取兼容项；新导出统一使用 1.0。

Manifest 的 draft、Catalog 的 candidate 和 notVerified 是内容状态。JSON Schema 的 draft/2020-12 是规范名称。它们都不改变第一版格式的稳定状态。

动作和参数采用逐字段白名单。Manifest 声明内容路径、原始文件 SHA-256、许可、能力、验证状态和 Ed25519 签名。official 内容仍须具备真实硬件验证记录。

签名输入为移除顶层 signature 后的 canonical JSON：对象键递归按 UTF-16 码元排序，数组保序，无空白，编码为 UTF-8。Catalog 的 manifestDigest 是包含 Manifest signature 的 canonical JSON SHA-256。

第一版 Manifest 与 Catalog 示例使用 固定公开测试公钥复验。对应私钥仅在生成进程内存在，没有写入仓库或文件系统。测试公钥、示例地址和签名均不是生产信任根或客户端接入凭据。

运行 npm run validate 检查 Schema、示例、引用、原始内容摘要、签名、撤销和内容边界。第一版冻结样例覆盖四类根对象和完整内部依赖；其 canonical JSON 摘要固定在测试中。自动化通过不能替代真实设备验收。
